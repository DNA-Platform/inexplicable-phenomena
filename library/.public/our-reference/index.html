The Book
1. What a book is here
1.1 Every book in this library extends the library's own, so what a book is here is decided once and a change to it reaches all of them.
1.2 The book class is the layout: the running head, the front drawn from what the book's cover says, then the chapters, and after them the file's page the editor shows. Its file is where the library's theme is registered, once, on the class every book extends.
1.3 A cover's route opens at the top of the page; every other bookmark turns as the framework does, and a page opens at its top, never scrolled down, on my word of 16 November 2026.
1.4 Every chapter but the cover and the table is navigated, said by the book at its bond before the bond reaches the chapters: the arrow looking back, the square to the table, the arrow looking on, above and below.
2. The book's class and what it says of every book
2.1 The class stands beside this chapter as its code, borrowed on 30 October 2026 from the binder's own test library, whose manual the team wrote, and rebuilt from here by sketches rather than kept.
2.2 The theme it registers is The Theme; the running head it draws is The Running Head and the Byline; the front and the navigation are The Faces.
2.3 It says of every book the editor, the paging and the page mode, in that order, so the editor's layer is the book's nearest and the page is the mode a book opens in unless its own class says the editor after; and at its bond it hangs a branch on every entry of the table of contents, so the table can be the editor's tree. Both are The Reference Manual's, sections 4 and 5.

// THE HEADING IS MINIMAL AND THE BYLINE IS NOT DRAWN, Doug, 2026-11-16: first "Why does every chapter need a
// title and author?!?", then "what happened to a minimal heading, at least with the book title" — the running
// head is the book's title alone, a way to the table and, from the table, to the cover; the author lives on the
// front and in the table of contents.
export class $TheLibrary extends $Book {
    override write(): ReactNode {
        const RunningHead = $(runningHead);
        const Front = $(front);
        const FilePage = $(filePage);
        return (
            <>
                <RunningHead chapter={this.cover} />
                <Front chapter={this.cover} />
                {super.write()}
                <FilePage chapter={this.cover} />
            </>
        );
    }

    // A PAGE OPENS AT ITS TOP, Doug, 2026-11-16: "We need pages to open at the top... not scrolled down" — a
    // turn lands on the page's top with the running head in view, never past it.
    protected override turn(): void {
        window.scrollTo(0, 0);
    }

    // EVERY BOOK HAS THE EDITOR AND OPENS ON THE PAGE, Sprint 131, Doug, 2026-11-17: "Reference manuals should
    // default to full but maybe appendix authors can choose?" — the editor stands before Paginated so its layer is the
    // book's nearest and the grid reaches the chapters; the page is the default, and a manual's own class says the
    // editor after this, which suppresses it.
    protected override $Define(): void {
        super.$Define();
        this.annotations.add(this,
            <Editor />,
            <Paginated />,
            <PageMode />
        );
    }

    // EVERY CHAPTER BUT THE COVER IS NAVIGATED, said by the book at its bond and before the bond reaches the
    // chapters, so the lines the format holds are bound with them. The cover's page is the front; a chapter that
    // already says Navigation in its own text keeps its own. Doug, 2026-11-16: "You need next and table of
    // contents and previous on the top and bottom of every chapter in the library."
    protected override $Bound(): void {
        const Navigated = $(navigated);
        const Branch = $(branch);
        // EVERY ENTRY OF THE TABLE IS A BRANCH, Sprint 131: the table is the editor's tree, each row's files hung
        // beneath it as leaves; the branch reads the chapter the row means and draws nothing for a row with none.
        for (const section of this.table?.text.find($Section) ?? [])
            for (const entry of section.text.find($Paragraph))
                if (entry.annotations.expressed($Branch) === undefined) entry.annotations.append(this, <Branch />);
        for (const chapter of this.text.find($Chapter)) {
            // THE TABLE WEARS NO NAVIGATION, Doug, 2026-11-16, pressing the square and landing on the table's own
            // page: "WHAT IS THIS!!!" — the table of contents is the book's navigation and carries none of its own.
            if (chapter.is($Cover) || chapter.is($TableOfContents) || chapter.text.find($Navigation).length > 0) continue;
            chapter.annotations.add(this, <Navigated />);
            chapter.annotations.define();
        }
        super.$Bound();
    }
}

The Theme
1. The values and the parts of a theme
1.1 A theme is a set of values, the font, the size, the leading, the measure, the space, the ink, the paper, the link, and the parts that use them: the page, the levels of a book, the labels, the links, the apparatus, the figures, the front, the plate, the navigation and the listing.
1.2 The file beside this chapter is the one the book registers, The Book 1.2. It began as the test library's theme as borrowed, a serif on warm paper, and has been rewritten part by part as the sketches said what this library's own looks like: white paper, Georgia at seventeen, one hairline under the running head, the link's teal on the running head and the links alone.
1.3 A theme is composed of parts so that a subclass changes one and keeps the rest; every selector in it is a mark of what a writing is.
2. The theme's listing part
2.1 The listing part dresses the reference manual's listing in the numbers measured off my own library's manual on 17 November 2026, The Reference Manual 3.1: JetBrains Mono at 12px on a 20.4px line, the ink pale on a night of deep teal, keywords sky, strings amber, names mint, comments dimmed, the numbers in a 44px column of brass, and the light palette when the book wears the light switch.

    }
}

        if (own === undefined) return false;

        const own = this.$annotation;
        if (own === undefined) return;
        const annotations = [book.$is].flat().filter(annotation => !this.$family.includes(annotation));
        book.$is = [own, ...annotations];
    }
}

The Specification
The specification of a specification, written in its own form. I chose the form of a legal document on 16 November 2026, its anatomy the contract's — recitals, articles, clauses, defined terms, provisos, schedules — evolved for a library that specifies deliverables. The form is the library's; a subject may redress it to fit its style, as a theme redresses a page. Mathematics writes its own in The Specification, and the first full instance is the statement of work of The Symmetry of Arithmetic.
1. Purpose
1.1 A specification is the formal identification of a deliverable — the thing agreed between buyer and seller in a service contract. It fixes what the deliverable must be, uniquely, so that candidates can be judged against it and the right one recognized when it is found. The specification is the legal document; the deliverable is not.
1.2 The specification is the anchor for the work. The work meets the specification part by part, and the deliverable cites each part as it is met.
1.3 A demand that cannot be checked has specified nothing, and a demand is stated so that it can fail.
2. The parts
2.1 The preamble — the contract's recitals. What the document is and the choice it records, standing before the numbered sections and carrying no number.
2.2 The sections — the contract's articles. Each bears a number and a name, and the sections run in one sequence.
2.3 The clauses. A section nests numbered parts: clause 2.3 is the third clause of section 2. A clause nests further where its matter requires it.
2.4 The labels — the contract's defined terms. A recurring kind of clause carries a letter and a number, defined where the clause is stated; in the first instance, the known results K, the constraints C, and the open determinations O.
2.5 The provisos. Where a demand is motivated, the motivation stands beside it and says so.
2.6 The tables. A table states what a table states best — axioms, results, tests — and its rows are clauses carrying their labels.
3. Citation
3.1 The specification references itself. Any clause cites any other by its number or its label, in free-form citation language, and every citation is a link to the clause it names.
3.2 A specification is highly connected: where a clause depends on another, motivates it, or constrains it, it says so by citation.
3.3 Citation reaches across the project's documents: the specification cites the progress by its labels, and the progress cites the specification by its numbers.
4. Boundary
4.1 The specification states where it ends. Nothing outside the boundary binds the work.
4.2 What stands after the end is the schedules — the contract's annexes: reference bearing on the work and binding none of it.
5. Interpolation
5.1 What is specified and not yet found stands as a placeholder for itself, in a brace naming the open determination it waits on.
5.2 The work closes when the last placeholder is replaced by the thing it stands for.
6. Permanence
6.1 A specification is not thrown away. It is updated when its parts are found inconsistent, since an inconsistent specification has specified nothing.
6.2 A change is made by changing the specification, in the context of all its other parts.
7. The implementation
7.1 The implementation meets the specification part by part, and cites each part as it is met, by its number or its label.
7.2 A citation from the implementation leads to the part it names, and the specification stands beside what implements it: the two forms are each reachable from the other.
7.3 A justification is the annotation form of this relationship: it says how the implementation satisfies a part, citing the part by number.
8. Format
8.1 The format chosen here is the legal document, as this chapter is written: a preamble, then numbered, named sections of numbered clauses.
8.2 A subject may change the format to fit its style. The form of sections 1 to 7 — purpose, parts, citation, boundary, interpolation, permanence, implementation — is kept, and the tree of section 9 with it; the dress is the subject's.
9. The tree
9.1 A specification always has numbers or codes, always has nesting, and the numbers nest — the anatomy of 2.3. It need not be only a list of lists, but it can be imagined as one.
9.2 The tree is a projection of the document. Every operation below is an act on the projection, never on the document: a moved part keeps its code and its annotations, because the code carries identity, and permanence (6) is untouched.
9.3 Unique showability: at any moment every part is on the page for exactly one reason or off it for exactly one reason — shown; folded away by an ancestor; hidden by the reader; or standing aside while one part shows alone. Each reason has exactly one control and one inverse, so any view can be read back, and any view can be left.
9.4 The operations, each with its inverse, at every level of the tree:
9.4.1 Fold — a press on any part's heading folds its children beneath a quiet count; a second press unfolds.
9.4.2 Hide — a part hides entirely from its gutter; show-all returns every hidden part.
9.4.3 Only — a part stands alone, the one thing on the screen, its ancestors' headings standing as its path; at most one part stands alone at a time; pressing it again, or everything, returns the rest. A figure's mark (9.8) is a second door to this state, left by the same inverses.
9.4.4 Move — parts move beside one another to compare, across sections and at any level; sections reorder among themselves.
9.4.5 Reset — the strongest inverse: every part reseated in the document's own order, every fold, hide and alone-state cleared at once. Each part carries its home and its seat from the rendering, so the return is exact.
9.5 The bar: the whole tree's verbs stand up top — the annotation layer's square, sections folding the tree to its headings where they can be cleared and reordered, expand unfolding every level, show all while something hides, everything while one part stands alone, and reset always.
9.6 The annotations are consistent: one form for every subject — a one-line mark in a single rail at the writing's right edge, level with its subject, stacked so marks never collide, and the writing never moves to make room. The why stands on the mark's hover and the claim on its press; a relation's visible end still draws, citing across; a mark draws only while its subject stands and its section's square is on. No square starts checked — the layer stands dark until the bar's square lights every mark.
9.7 The code of this tree stands in the appendix: the specification held as an object, its rendering operable — and the appendix page is that code run on this specification itself.
9.8 The figure — an annotation naming an object of the specification by its code, with a title and a caption. Its mark rides the rail; its press is 9.4.3 performed on its object, dressed: the title above, the caption beneath, unshown until the title is pressed. A figure without a title is just the writing, alone.

// the squares rule the annotation layer with the bar's square as every section's at once, a heading press
// folds at any level, a mark with a claim turns the page back to the citation that claims it, and a
// citation press lands as it always has. Every act that changes what stands re-lays the rail.
export class $Markdown extends $Paragraph {
    $identifier = '';
    $tree = false;

    follow = (press: MouseEvent<HTMLDivElement>): void => {
        const root = press.currentTarget;
        const pressed = press.target as Element;
        const x = pressed.closest('.pc-x');
        if (x !== null) {
            x.closest(x.classList.contains('pc-sec-x') ? '.pc-spart' : '.pc-part')?.classList.add('pc-hidden');
            rail();
            return;
        }
        const ring = pressed.closest('.pc-o');
        if (ring !== null) {
            const one = ring.closest('.pc-part, .pc-spart');
            const was = one?.classList.contains('pc-the-one') ?? false;
            clearAlone(root);
            if (!was && one !== null) alone(root, one);
            rail();
            return;
        }
        if (pressed.closest('.pc-showall') !== null) {
            root.querySelectorAll('.pc-hidden').forEach(part => part.classList.remove('pc-hidden'));
            rail();
            return;
        }
        if (pressed.closest('.pc-return') !== null) {
            clearAlone(root);
            rail();
            return;
        }
        if (pressed.closest('.pc-sections') !== null) {
            root.querySelectorAll('.pc-spart').forEach(part => part.classList.add('pc-folded'));
            rail();
            return;
        }
        if (pressed.closest('.pc-expand') !== null) {
            root.querySelectorAll('.pc-folded').forEach(part => part.classList.remove('pc-folded'));
            rail();
            return;
        }
        if (pressed.closest('.pc-reset') !== null) {
            root.querySelectorAll('.pc-hidden, .pc-folded').forEach(part => part.classList.remove('pc-hidden', 'pc-folded'));
            clearAlone(root);
            const boxes = new Map<string, Element>([['root', root]]);
            root.querySelectorAll('[data-box]').forEach(box => {
                const kids = box.querySelector(':scope > .pc-kids');
                if (kids !== null) boxes.set(box.getAttribute('data-box') ?? '', kids);
            });
            [...root.querySelectorAll<HTMLElement>('[data-home]')]
                .sort((a, b) => Number(a.getAttribute('data-seat')) - Number(b.getAttribute('data-seat')))
                .forEach(node => boxes.get(node.getAttribute('data-home') ?? '')?.append(node));
            rail();
            return;
        }
        const master = pressed.closest('.pc-anno-master');
        if (master instanceof HTMLInputElement) {
            root.querySelectorAll<HTMLInputElement>('.pc-sec-anno').forEach(box => { box.checked = master.checked; });
            rail();
            return;
        }
        if (pressed.closest('.pc-sec-anno') !== null) {
            const boxes = [...root.querySelectorAll<HTMLInputElement>('.pc-sec-anno')];
            const all = root.querySelector<HTMLInputElement>('.pc-anno-master');
            if (all !== null) all.checked = boxes.every(box => box.checked);
            rail();
            return;
        }
        const mark = pressed.closest('.pc-anno');
        if (mark !== null) {
            if (mark.classList.contains('pc-fig')) {
                const subject = document.getElementById(mark.getAttribute('data-for') ?? '');
                const one = subject?.closest('.pc-part, .pc-spart') ?? null;
                const was = one?.classList.contains('pc-the-one') ?? false;
                clearAlone(root);
                if (!was && one !== null) {
                    alone(root, one);
                    const title = mark.getAttribute('data-fig-title') ?? '';
                    if (title !== '') {
                        const head = document.createElement('p');
                        head.className = 'pc-fig-head';
                        head.textContent = title;
                        head.title = 'The caption stands beneath; press the title to show it.';
                        const caption = document.createElement('p');
                        caption.className = 'pc-fig-cap';
                        caption.textContent = mark.getAttribute('data-fig-caption') ?? '';
                        one.before(head);
                        one.after(caption);
                    }
                }
                rail();
                return;
            }
            const claim = mark.getAttribute('data-claim');
            if (claim !== null) {
                const turn = (): void => {
                    const flip = document.getElementById('pc-flip');
                    if (flip instanceof HTMLInputElement) flip.checked = false;
                    document.getElementById(claim)?.scrollIntoView({ block: 'center' });
                };
                const doc = document as Document & { startViewTransition?: (update: () => void) => unknown };
                if (doc.startViewTransition === undefined) turn();
                else doc.startViewTransition(turn);
            }
            return;
        }
        const head = pressed.closest('.pc-fig-head');
        if (head !== null) {
            head.parentElement?.querySelector('.pc-fig-cap')?.classList.toggle('pc-cap-shown');
            return;
        }
        const heading = pressed.closest('.pc-spart > h2, .pc-spart > h3');
        if (heading !== null) {
            heading.parentElement?.classList.toggle('pc-folded');
            rail();
            return;
        }
        const citation = pressed.closest('a[href^="#cite-"]');
        if (citation === null) return;
        press.preventDefault();
        const landing = document.getElementById(citation.getAttribute('href')?.slice(1) ?? '');
        landing?.scrollIntoView({ behavior: 'smooth', block: 'center' });
    };

    grab = (grip: DragEvent<HTMLDivElement>): void => {
        const part = (grip.target as Element).closest<HTMLElement>('.pc-part, .pc-spart');
        if (part === null) return;
        dragged = part;
        grip.dataTransfer.setData('text/plain', 'part');
        grip.dataTransfer.effectAllowed = 'move';
    };

    over = (drag: DragEvent<HTMLDivElement>): void => {
        const target = aim(drag.target as Element);
        unseat();
        if (target === null) return;
        drag.preventDefault();
        const box = target.getBoundingClientRect();
        target.classList.add(drag.clientY < box.top + box.height / 2 ? 'pc-before' : 'pc-after');
    };

    drop = (fall: DragEvent<HTMLDivElement>): void => {
        const target = aim(fall.target as Element);
        unseat();
        if (target === null || dragged === null) return;
        fall.preventDefault();
        const box = target.getBoundingClientRect();
        const before = fall.clientY < box.top + box.height / 2;
        if (dragged.getAttribute('data-level') !== '1' && target.classList.contains('pc-spart')) {
            const kids = target.querySelector(':scope > .pc-kids');
            if (kids !== null) {
                if (before) kids.prepend(dragged);
                else kids.append(dragged);
            }
        } else {
            target.parentElement?.insertBefore(dragged, before ? target : target.nextSibling);
        }
        dragged = null;
        rail();
    };

    settle = (): void => {
        unseat();
        dragged = null;
    };

    get append(): $Append | undefined {
        return this.chapter?.annotations.find($Append).find(append => append.$identifier === this.$identifier);
    }

    override write(): ReactNode {
        const append = this.append;
        if (append === undefined) return null;
        const connected = connect(marked.parse(html.copy(append.text), { async: false }));
        const rendered = this.$tree ? treeify(connected) : connected;
        return (
            <div
                className={this.$tree ? `pc-doc-${this.$identifier} pc-tree` : `pc-doc-${this.$identifier}`}
                onClick={this.follow}
                onDragStart={this.grab}
                onDragOver={this.over}
                onDrop={this.drop}
                onDragEnd={this.settle}
                dangerouslySetInnerHTML={{ __html: rendered }}
            />
        );
    }

    protected override $Define(): void {
        super.$Define();
        this.classes.add(this, 'pc-markdown');
    }
}

// THE IMPLEMENTATION CITES THE SPECIFICATION, Doug, 2026-11-16: "there needs to be some relationship between
// the spec and the implementation" — the deliverable cites the part of the specification it meets, by number
// or label, and the citation leads there: it flips the content to the project side and lands on the part named.
export class $Cite extends $Word {
    $part = '';

    // The part is read back from the clicked anchor's own text: the handler's instance predates the pass
    // that applies props to the held one, so the rendered citation is the one source the click can trust.
    // The flip and the landing scroll both run inside the view transition's update, so the dissolve lands
    // directly on the cited clause.
    follow = (press: MouseEvent<HTMLAnchorElement>): void => {
        const part = press.currentTarget.textContent ?? '';
        const turn = (): void => {
            const flip = document.getElementById('pc-flip');
            if (flip instanceof HTMLInputElement) flip.checked = true;
            cover();
            rail();
            document.getElementById(place(part))?.scrollIntoView({ block: 'center' });
        };
        const doc = document as Document & { startViewTransition?: (update: () => void) => unknown };
        if (doc.startViewTransition === undefined) turn();
        else doc.startViewTransition(turn);
    };

    override write(): ReactNode {
        return <a onClick={this.follow}>{this.$part}</a>;
    }

    protected override $Define(): void {
        super.$Define();
        this.classes.add(this, 'pc-cite');
    }
}

// THE FIGURE, Doug, 2026-11-18: "a type of annotation called a Figure (this is a new idea) that contains
// something object like that is in the spec as a reference, and when clicked, the thing should be the only
// thing visual with a title and caption or if it's more writing or it can just be the writing. Captions
// should not be shown to start" — an annotation said in the chapter, referring to its object by mention,
// never a runtime id. It draws nothing where it stands; its mark rides the rail beside the coverage, and
// its press is the only-operation performed on its referent, dressed — the title above, the caption
// beneath, unshown until the title is pressed. A figure without a title is just the writing, alone.
export class $Figure extends $Paragraph {
    $part = '';
    $title = '';
    $caption = '';

    override write(): ReactNode {
        return (
            <span
                className="pc-figure"
                data-part={this.$part}
                data-title={this.$title}
                data-caption={this.$caption}
            />
        );
    }

    protected override $Define(): void {
        super.$Define();
        this.classes.add(this, 'pc-figure-seat');
    }
}
